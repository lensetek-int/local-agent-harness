THE ARCHITECTURAL DIFFERENCE

Why Frontier Agent Harnesses Fail on SLMs — And Why Lean Works

Frontier harnesses (Claude Code, OpenAI Codex, Antigravity, OpenCode) were built for 100B+ cloud models or 14B–30B+ GPU setups. On 3B edge SLMs, their heavy prompt overhead and strict schemas cause instant failure.

Frontier Agent Harnesses Cloud-First / Large-Model Centric

Claude Code, OpenAI Codex, Antigravity, OpenCode

  • ❌
    Massive System & Tool Schema Overhead (4,000 – 15,000+ tokens)

    Built for 100B+ frontier models with 128K+ context windows. Injects dozens of strict tool schemas and long instruction prompts before the user even types a word.

  • ❌
    Cannot Run 3B SLMs Reliably (Schema Drift & Context Collapse)

    Even when pointed at a local endpoint, 3B GGUF models fail strict JSON/diff tool schemas, hallucinate arguments, and overflow 8K context—practically requiring 14B–30B+ GPU models.

  • ❌
    No Bundled CPU SLM Runtime

    Cloud-first harnesses (Claude Code, Antigravity) target hosted APIs and do not ship a self-contained llama.cpp CPU engine with 8-bit KV-cache tuning for 2.5 GB RAM laptops.

  • ❌
    Cloud API Cost, Telemetry & High-VRAM Barrier

    Requires paid cloud subscriptions/APIs (sending code and prompts off-device) or expensive high-VRAM GPUs to run large local coding models.

Lensetek Lean Harness Edge-First / Autonomous

Purpose-Built for Local SLMs & Local LLMs

  • ✅
    Ultra-Lean Token Budgeting (< 350 tokens initial prompt)

    Minimalist ReAct instruction set. Leaves >90% of the context window wide open for actual user prompts, file contents, and step-by-step reasoning.

  • ✅
    Runs Edge SLMs (3B) with Scalability to Local LLMs (7B / 14B)

    Flawlessly drives 3B edge models on modest hardware, yet instantly scales to 7B or custom local models via /model switch and /model add.

  • ✅
    Zero GPU Requirement & Low RAM (< 2.5 GB)

    Optimized for commodity CPUs (everyday laptops, mini PCs, SBCs). Pure GGUF execution with 8-bit KV cache compression without requiring discrete GPUs.

  • ✅
    Built-in Anti-Hallucination & Loop Circuit-Breakers

    Small models can spiral when a tool fails. Our harness includes runtime interceptors and retry caps that detect failure patterns and rescue the agent.

  • ✅
    100% Air-Gapped & True Data Sovereignty

    Runs entirely offline with zero cloud telemetry. Your source code, sensitive documents, and prompt thoughts never leave your local machine.

Frequently Asked Questions

Direct answers about local CPU inference, on-demand plugins, privacy, and how Lensetek outperforms heavy cloud frameworks on 3B–7B models.

What is Lensetek Lean Agent Harness?

Lensetek Lean Agent Harness is an open-source, ultra-lean (< 5 MB) local AI agent runtime designed for 3B to 7B GGUF models. It runs 100% locally on standard laptop CPUs without a GPU or cloud API keys, enabling autonomous coding, file editing, MCP tool calling, headless web search, and an optional Web Workspace.

Can it run on a standard laptop CPU without a GPU?

Yes. Lensetek Agent automatically downloads and manages the official llama.cpp CPU runtime (llama-server) with KV-cache quantization and Flash Attention, allowing 3B GGUF models to run smoothly on standard laptops with less than 2.5 GB of RAM.

Why can't Claude Code, Codex, Antigravity, or OpenCode run 3B SLMs reliably?

Cloud-oriented frameworks inject 3,000–8,000+ tokens of boilerplate overhead, causing small 3B–7B models to lose focus or overflow 8K context windows. Lensetek keeps prompt overhead minimal (< 600 tokens) and grounds the active workspace directly so small local models execute tools accurately.

How do on-demand plugins like Web Workspace (webui) work?

Core Lensetek stays ultra-lightweight, while optional capabilities are installed on demand via /plugins or lensetek --plugins install <id>. The official webui plugin launches a responsive light-first Web IDE at http://127.0.0.1:3001 with real project file read/write/edit, live tool cards, and interactive permission approvals.

Is my source code or credential data sent to the cloud?

No. Inference and file operations run 100% locally on 127.0.0.1. Sensitive files such as .env, private keys (.pem/.key), and .git internals are strictly blocked from WebUI API access and workspace context snapshots.
